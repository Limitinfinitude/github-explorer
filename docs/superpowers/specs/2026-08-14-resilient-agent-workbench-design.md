# 可靠会话与可执行项目工作台设计

## 目标

让 Agent 在执行本地工作时仍然正常回应用户，并让任务不再依附当前页面的 SSE 连接。项目工作台使用每个项目固定的独立会话，通过现有 `LocalAgentRuntime` 真正执行体检、环境准备、启动、理解和验证任务。

## 已确认问题

1. `LocalAgentRuntime.run()` 直接运行在 SSE 请求生成器中，连接关闭会触发 `task_interrupted`。
2. 前端只把完成后的回复写入 Chat；运行中的步骤、部分文本和任务 ID 都在 `ChatPanel` 局部状态中。
3. 页面重新挂载只恢复 `waiting_approval`，不会恢复 `running`、`incomplete`、`failed` 或已完成但尚未写入前端的任务。
4. 模型在工具轮数耗尽后可能返回空文本，当前格式化器无法用工具与事件事实生成有效答复。
5. “完成得如何、为什么失败”等状态问题仍允许工具，导致 Agent 再次执行项目而不是先回答。
6. 项目工作台后端和前端均为只读投影；阶段依赖关键词猜测，所谓下一步没有动作入口。

## 架构

### 后台任务与事件订阅

新增进程内 `AgentTaskSupervisor`。启动接口先创建并持久化任务，再由 supervisor 的 `asyncio.Task` 独立消费 `LocalAgentRuntime.run()`。浏览器通过任务事件 SSE 按 `sequence` 订阅 SQLite 事件；断开订阅不会取消后台任务。服务重启仍按现有规则把未完成任务标为 `interrupted`，不伪造恢复。

现有 `/api/agent/chat/stream` 保留兼容，新的 React 客户端使用：

- `POST /api/agent/tasks/start`
- `GET /api/agent/tasks/{task_id}/events?after_sequence=0`
- `GET /api/agent/sessions/{session_id}/active-task`

### 会话恢复

Chat 在发送时立刻持久化用户消息与任务占位。重新进入页面时读取最新非终态任务；运行中则从事件 0 重放并继续订阅，终态则重新投影会话历史。事件订阅中的 `error` 只作为过程事实展示，必须继续等到最终 `done`，避免丢失终态总结。

### 正常回复与收尾

状态追问使用上一任务的结构化事实，并禁用工具。执行任务不要求每轮输出聊天文本，但终态必须包含：回答用户目标、已完成、未完成、错误/恢复、验证和下一步。模型终态为空时由 Runtime 用事实账本生成确定性回复。失败工具结果继续进入下一轮，提示模型必须先解释失败原因并改变方案；相同失败仍由现有限制终止。

### 固定项目会话

项目 ID 已由工作区路径稳定哈希生成，项目会话固定为 `project-session-<digest>`。项目动作启动前把该会话绑定到项目工作区，不复用普通聊天上下文。

工作台第一版提供五个真实动作：

- 项目体检
- 准备环境
- 启动并验证
- 生成项目导读
- 运行验证

动作都调用同一个后台任务启动服务。工作台显示当前任务状态，并提供“打开项目对话”；阶段与下一步改为基于工具、验证、进程和终态事实推导，不再只看用户问题关键词。

## 错误与边界

- 同一项目会话已有运行或待确认任务时拒绝重复启动。
- 项目不存在、工作区不存在、动作非法时返回明确 4xx。
- 页面切换、组件卸载和订阅重连不取消任务；只有“停止任务”调用取消接口。
- 服务重启导致的中断明确显示，允许从项目工作台重新发起，而不声称自动续跑。
- 工作台不直接执行 shell，不增加第二条状态机或第二套权限模型。

## 验收

1. 启动任务后关闭事件订阅，后台任务仍完成并落库。
2. 重新订阅可按顺序重放事件并收到唯一终态。
3. 页面切到探索/设置再返回，运行消息和最终回复不丢失。
4. 状态追问不调用工具，并引用上一任务真实状态。
5. 模型最终文本为空时仍返回事实化的非空回复。
6. 五个工作台动作使用稳定项目会话并进入唯一 Runtime。
7. 工作台阶段和下一步由真实证据变化驱动。
8. 后端、前端测试与生产构建通过，服务只监听 `127.0.0.1:7788`。
