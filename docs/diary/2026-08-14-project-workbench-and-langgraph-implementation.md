# 项目工作台与 LangGraph 兼容层实施记录

> 时间：2026-08-14（Asia/Shanghai）

## 遇到了什么

产品定位确认后，前端原有 Chat、Explore、Activity、Settings 入口不能简单删除：开发者需要完整运行记录、工具流水账、失败恢复、工作区、进程和 LangSmith 数据来测试 Harness 和继续开发；但初学者又不应该被流水账淹没。

第一版工作台还把最近的 `task_id` 当作项目 ID，导致同一工作区的多轮任务看起来像多个项目，无法稳定切换和复盘。

LangGraph 审计结果也不是“可以立即删除”：新的 `LocalAgentRuntime` 已经是主 SSE Agent 链路，但旧 `/api/chat`、分析/学习路径、搜索解释、setup/confirm 和 Swarm 仍直接调用 LangGraph。

## 发现了什么

1. 正确的产品结构是“项目旅程摘要 + 同页可展开的开发者证据层”。摘要展示阶段、状态、下一步、变更、验证和访问事实；证据层保留事件、工具、参数、cwd、命令、退出码、文件、测试、进程、恢复和观测数据。
2. 项目身份应由规范化 `workspace_root` 派生，任务是项目下的时间线项。Windows 大小写、斜杠和末尾分隔符差异不能产生不同项目。
3. 证据接口不能直接暴露历史 task/tool JSON；即使设置页掩码，也必须在投影边界递归脱敏 `api_key`、`authorization`、`token`、`password` 和 `secret`。
4. LangGraph 代码规模占 `src` 约 0.32%，但入口影响高。删除依赖前必须知道旧入口是否仍被使用，因此需要 legacy 调用计数和替代路径。
5. 真实页面验收发现移动端自动化如果直接点击收起侧栏中不可见的导航 DOM，会得出错误结论；按真实用户路径先打开侧栏再点击后，项目工作台切换正常。

## 分析

“保留流水账”与“界面更好看”不是冲突关系，冲突来自信息层级。把开发者数据删除会损害开源开发和 Harness 评测；把它默认全部展开又会伤害初学者。解决方式是同一事实源、两层投影、默认折叠和按项目/任务筛选。

LangGraph 当前应被视为 legacy compatibility surface，而不是新主链。让它继续扩展会形成第二套编排与状态事实；立刻删除又会破坏旧接口。最小风险策略是保留、隔离、计数、逐路由迁移，最后根据调用量和回归结果移除或独立实验化。

## 改进计划

### 本轮已实施

- 新增 `PRODUCT.md`，固定产品定位、用户优先级、双层信息原则和 LangGraph 处置决策。
- 新增项目工作台入口，包含项目旅程：体检、跑起来、看懂、实验室、验证、记录。
- 新增项目概览与开发者证据接口；证据层默认折叠，保留完整事件和文件事实。
- 新增稳定项目列表：按规范化 workspace root 聚合任务，支持多个项目选择。
- 项目切换后概览、工作区、阶段、失败状态和事件全部从所选项目重新投影。
- 开发者证据递归脱敏，避免密钥、Authorization 和 token 进入开源 UI/API。
- 为 LangGraph 旧入口增加本地调用计数、替代路径提示和观测接口字段 `legacy_graph`。
- 保留原有 Explore、Activity、Chat、Settings，不删除运行记录；Activity 继续作为跨项目审计视图。

### 下一批

1. 将项目页的阶段点击接入只读投影，不触发隐式工具调用。
2. 把完整工具参数、命令、退出码、进程和 LangSmith Trace 详情接入证据层的筛选和复制操作。
3. 迁移 `/api/chat`、分析/学习路径和 `/api/explain` 到 Runtime 只读任务，并写入统一 Event Store。
4. 迁移 setup/confirm 到 Runtime approval/resume。
5. 继续记录 LangGraph 旧入口调用量；调用量归零且替代回归通过后，再评估移除默认依赖。

### 未完成事项

LangGraph 尚未剔除。它已被隔离并可观测，但旧 API 迁移还未进行；项目工作台的阶段按钮目前是信息展示，尚未驱动独立的阶段投影或 Runtime 任务。以上是有意保留的下一阶段边界，不是本轮遗漏。
