## 5. 失败痕迹（诊断）

全部为 tool 类（共 14 条），属于 agent 探索过程中的正常试错，未影响完成：

- `run_command 命令退出码: 1/2`（12 条）：多为首次命令路径/参数错误后的重试
- `install_dependencies 虚拟环境不存在`（1 条）：ghgrab 是 Node 项目误调 Python venv 工具
- `list_directory .venv 不存在`（1 条）：环境未就绪时的目录探测

无 environment / harness / model 类失败。修复的链路问题：
1. **全局 Python 3.12 环境损坏**（httpx/httpcore 缺 `_trace.py`、pip 的 `pip._vendor.rich` 报错）→ 改用 Python 3.13 跑评测；事后已修复：用 Python 3.13 下载 pip wheel 解压覆盖坏文件 + 重装 httpcore，3.12 恢复健康。
2. **run_eval.py reset 保护逻辑**：ghgrab 预编译二进制不被 git 跟踪，`git clean -fdx` 会误删 → 存到项目同盘 stash 再恢复（跨盘 rename 会报 WinError 17）；实际发现 `npm install` 的 postinstall 脚本会自动重建二进制。

### 工具误用复盘（ghgrab 的 install_dependencies 失败）

ghgrab 是「Node 为主 + Python 打包壳」的混合项目（有 pyproject.toml 用于发 PyPI），
detect 判定为 python + node 双语言。agent 在未先 ensure_venv 时调用 install_dependencies，
Python 分支报「虚拟环境不存在」。属正常探索试错（agent 随后自行纠正、最终 completed），
harness 无需修改；结论：混合项目（多语言打包壳）是 edge case，报错信息已足够引导 agent。
