◈ 分层判断标准（这次按代码组织，不凑层数）
① 需要懂任务吗？需要 → 认知（上下文组装和记忆是决策输入，所以归认知）；只懂规则 → 闸门 / 执行。② 闸门不是层：权限 / 边界 / 预算 / 验收只是动作路径上的检查点，不产生任何动作——所以画成条，「什么时候停」的唯一来源是 LoopGuard 纯策略（只答「允许吗 / 该停吗」，绝不调 LLM）；治理层仅有两处 LLM 接缝（压缩摘要 + guardian 安全审查），都不替 Agent 决策。③ 编排在循环之外：管任务生死，不管单轮推理。④ 脊柱是纵切：观测贯穿所有层，不是其中一层。⑤ State 三分已固化：state_schema.py 把任务状态拆成信封 / 认知 / 运行（state["run"]）/ 环境四分区，测试强制任何新键先归类——超级 dict 有了法律。一次动作只向下穿过一个闸门；观察沿原路回传。点击任意模块查看对应实现与源码位置。
◈ 全景
接口接单 → 编排决定任务何时跑 → 认知循环决定下一步（decide）→ 治理闸门决定能不能做（govern）→ 执行层调度真实执行体 → 世界被改变并回传观察 → 脊柱全程记录。认知层的发动机（模型接入）内嵌在层内，因为它只被循环调用。
