## 2. 判分脚本机制（本轮核心改进）

每个项目配 `checks/<name>/check.py`，**独立于 agent 运行**：
- 输入：工作区路径；输出：结构化 JSON `{"status": "pass"|"fail"|"error", "checks": [...], "reason": "..."}`
- run_eval.py 在 agent 任务完成后自动调用判分脚本，结果写入 record（`check_status`/`check_checks`/`check_reason`）
- `grade_of()` 优先使用 `check_status`：pass→passed，fail→failed，error→error；无判分脚本时回退 agent 自述
- homebox 判分脚本自起/自停进程（不依赖 agent 残留进程），随机端口避免冲突

## 4. 关键发现：外部判分 ≠ agent 自述

**r2-fun-2 的 homebox**：agent 自述 `incomplete`（未走完自己设定的流程/未宣布完成），
但**判分脚本 pass**（二进制存在 + HTTP 200 + HTML + API 探活全部达标）→ grade = **passed**。

这正是「判定看结果」的落地：agent 没「说」完成，但结果达标，判通过。
反向场景（agent 说完成但判分失败）会在后续轮次中暴露——本批未出现。

## 7. 过程中修复的问题

1. **zcode 重启导致评测中断**：homebox 任务挂死在 harness（memory 里 `running` 状态但无活动连接），
   session 冲突导致后续 start 返回 409 → 通过 `/api/agent/tasks/{id}/cancel` 取消挂死任务后恢复。
2. **run_eval.py 判分脚本集成**：新增 `run_check()`（调用 `py -3.12 checks/<name>/check.py`）、
   `grade_of()` 判分优先、结果文件记录判分明细。
3. **判分脚本断言修正**：yj 的 `-yj` 是 YAML→JSON（JSON→YAML 用 `-jy`）；sttr 的 base64 命令是
   `base64-encode`/`base64-decode`；python-chess 的 fen 白兵是大写 `P`、将军断言改用 Scholar's Mate 杀棋。
4. **harness 服务器重启**：3.12 全局环境缺 fastapi → 改用项目 `.venv`（fastapi 0.141 + uvicorn 0.52）启动。
