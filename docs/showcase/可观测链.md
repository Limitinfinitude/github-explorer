# 可观测链设计

用户为什么能"看见" agent 在做什么：单一编排链 + 事件账本 + 流式推送。

## 架构

```
AgentTaskSupervisor ──> LocalAgentRuntime ──> Tool pipeline
        │                    │                    │
        └──── SQLite 唯一事实源（任务/事件/工具账本/工件）
```

## 观测通道

| 通道 | 机制 | 用户看到 |
|---|---|---|
| 流式输出 | OpenAI SSE / Anthropic messages.stream 逐 chunk | 思考过程（thinking）+ 文本逐 token 出现 |
| 工具卡片 | tool_call/tool_result 事件 | 每次工具调用：名称、参数、结果、耗时、成败 |
| 旁白 | 模型只调工具不说话时，harness 生成"正在做什么" | 读文件/执行命令/启动服务… |
| 事件账本 | SQLite 全量事件 + sequence 回放 | 任务结束仍可复盘每一步（thinking/工具/叙述不丢失） |
| 大结果工件 | >12k 字符的工具结果存 artifact，模型只见 preview | 完整结果可回溯查看 |
| 终态仲裁 | result-priority v2 | 判定依据可见：验证/验收证据 + 失败诊断 |

## 关键设计点

- **边说话边干活**：模型文本与工具调用交错推送，不是"先想完再执行"。
- **thinking 可视化**：thinking_effort off/high/max，思考块与正文分开渲染。
- **恢复能力**：中断任务可 resume，round_limit 自动放宽；pending 任务 reconcile 防悬挂。
- **上下文压缩可见**：压缩触发会记录 context_compacted 事件（源消息数、序列范围）。

## 为什么可观测 = 能力

- 调试：任何失败都能从事件账本定位到具体调用（r8/r9 的失败归因全部来自账本统计）。
- 评测：观测事件（tool_failures、rounds、tokens）直接构成分级与失败分类的数据源。
- 信任：结果判定基于证据（[evidence:file/check/process]），不是模型自述。
