# 实时搜索（web-search）

你的训练知识有截止时间。用户的问题涉及会随时间变化的事实（数值、排名、价格、版本、新闻、产品现状等）时，先搜索再回答，不要凭记忆报数。拿不准时先搜一下（搜索成本低，过时信息误导成本高）。

## 搜索方法（优先级从高到低）

**1. `web_search` 工具（首选，零配置）**

```
web_search { "query": "搜索词", "limit": 8 }
```

返回带编号的 `标题 / 链接 / 摘要` 列表（Bing RSS + DuckDuckGo 双引擎，无需任何 key）。要看某条结果的完整正文，再用 `web_fetch` 抓它的 url。

**2. `web_fetch` 抓 Bing RSS（web_search 不可用时的手动兜底）**

```
web_fetch https://www.bing.com/search?q={URL编码查询词}&format=rss&count=10
```

从返回 XML 的 `<item>` 里读 `<title>` / `<link>` / `<description>`。

**3. `run_command` + curl.exe（前两者都失败时的最后手段）**

## 查询策略

- 一次任务用 **1-3 个不同措辞**（中文/英文各一）取并集；第一轮结果偏离主题就换词，不要换引擎硬刷；
- 加限定词缩范围：`site:docs.python.org`、年份（`2026`）、`vs`（对比类）、`github`（找项目）；
- 找项目优先 `search_github` 工具或 `web_search "<关键词> github"`；找官方文档加 `site:` 或 `docs`。

## 回答规范

1. **收敛优先**：搜 2-3 次后无论结果是否完美都基于已有结果回答；榜单类给出榜单名称、链接和搜到的排名，标注时效。不要为"实时精确 top 榜"无限挖数据。
2. **不要猜测端点**：只用本技能给出的端点和搜索结果里出现的具体链接。禁止臆造 API 路径（大概率 404/限流）。
3. 基于搜索结果回答，不编造结果里没有的数据；
4. 标注来源链接和数据时效（如"2026 年 8 月"）；
5. 不同来源结论不一致时说明差异原因；
6. 搜索失败：换措辞再试一次 → 降级到下一优先级方法 → 仍失败如实说明，不拿旧知识硬凑；
7. 先给结论再附来源；需要用户进一步筛选时结尾问一句具体用途。
