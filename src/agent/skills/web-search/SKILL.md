# 实时搜索（web-search）

你的训练知识有截止时间。用户的问题涉及会随时间变化的事实（数值、排名、价格、版本、新闻、产品现状等）时，模型记忆可能过时——先搜索获取实时结果再回答，不要凭记忆报数。拿不准时先搜一下（搜索成本低，过时信息误导成本高）。

## 搜索方法（web_fetch 抓公开搜索端点，无需 key）

用 web_fetch 抓 Bing 的 RSS 搜索端点（返回结构化 XML）：

```
web_fetch https://www.bing.com/search?q={URL编码的查询词}&format=rss&count=10
```

要点：
- 查询词先用 URL 编码（如 `大模型排行榜` → `%E5%A4%A7%E6%A8%A1%E5%9E%8B...`），不确定编码时直接用中文也可以（web_fetch 会处理）；
- 一次搜索可用 1-3 个不同措辞的查询（中英文各一），取并集；
- 从返回的 RSS XML 里读 `<item>` 的 `<title>`（标题）、`<link>`（链接）、`<description>`（摘要）；
- 需要看某个结果细节时，用 web_fetch 抓该 `<link>` 的正文。

## 回答规范

1. **收敛优先**：搜索 2-3 次（不同措辞）后，**无论结果是否完美都要基于已有结果回答**。不要为了拿"实时精确 top 榜"无限挖数据——榜单类问题给出榜单名称、链接和搜索到的排名即可，标注时效。
2. **不要猜测端点**：只抓本技能给出的 Bing RSS 端点，以及搜索结果里出现的具体链接（`<link>`）。**禁止猜测未经验证的 API 端点**（如 `xxx.com/api/leaderboard` 之类）——这些大概率 404/限流，浪费轮次。
3. 基于**搜索结果**回答，不要编造结果里没有的数据；
4. 标注信息来源（链接）和数据时效（结果里的日期，如"2026 年 7-8 月"）；
5. 不同来源结论不一致时说明（榜单标准差异）；
6. 搜索失败（网络错误/无结果）时：换措辞再试一次，仍失败则如实说明，不拿旧知识硬凑；
7. 简短给出结论，再附来源；需要用户进一步筛选时在结尾问一句具体用途。
